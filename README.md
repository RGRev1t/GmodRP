# GmodRP · Администрация

Discord-бот для **администрации сервера**: приём, повышение, понижение, снятие,
выдача ролей, варны, предупреждения, чёрный список проекта (ЧСП), история действий,
логи, новости и обновления в каналы.

Никаких организаций, паспортов, шаблонов и «рангов» в базе. Должность — это обычная
роль Discord. Бот не создаёт роли: он показывает те, которые уже есть на сервере,
и выдаёт выбранную.

## Команды

Короткие, без групп:

| Команда | Что делает |
|---|---|
| `/принять` | Принять в администрацию. Параметры: участник, **SteamID**, **роль**, причина |
| `/повышение` | Повысить. Параметры: участник, **SteamID**, **роль**, причина |
| `/понижение` | Понизить. Параметры: участник, **роль**, SteamID (необязательно), причина |
| `/снять` | Снять с должности. Параметры: участник, **SteamID**, причина |
| `/выдать-роль` | Выдать роль участнику |
| `/выдать-варн` · `/убрать-варн` | Варн и снятие последнего активного |
| `/выдать-предупреждение` · `/убрать-предупреждение` | Предупреждение и снятие |
| `/выдать-чсп` · `/убрать-чсп` | Чёрный список проекта |
| `/поиск` | Найти администратора по нику, SteamID или Discord ID |
| `/инфо` | Карточка администратора |
| `/новость` | Обновление по шаблону: версия, билд, разделы изменений |
| `/канал` | Привязать канал: аудит, варны, ЧСП, общие логи, новости |
| `/стиль` | Компактный или цветной вид сообщений |
| `/лимит` | Предел варнов (по умолчанию 3) |
| `/помощь` · `/статус` | Справка и диагностика |

`SteamID` обязателен при приёме, повышении и снятии; при понижении — по желанию.
При повышении и снятии он должен совпадать с тем, что записан в карточке.

### Как это выглядит

```
/принять участник: @zakod steamid: STEAM_0:1:1234567 роль: @Хелпер причина: прошёл собеседование
/повышение участник: @zakod steamid: STEAM_0:1:1234567 роль: @Модератор
/понижение участник: @zakod роль: @Хелпер причина: ошибки в работе
/снять участник: @zakod steamid: STEAM_0:1:1234567 причина: ушёл сам
```

## Роли

Бот не хранит список должностей. Роль выбирается прямо в команде из ролей сервера —
на тестовом и на основном сервере это будут разные роли, и ничего привязывать не нужно.

Иерархия считается по позициям ролей Discord:

- нельзя трогать участника, чья роль выше или равна вашей;
- нельзя выдать роль, которая не ниже вашей;
- нельзя выдать роль, которая не ниже роли бота.

**Роль бота должна стоять выше всех ролей администрации.**

### Что происходит при `/снять`

Снимаются **все роли от «Хелпера» и выше** (которые бот может снять), а затем
выдаётся роль **«Игрок»**. Косметические роли ниже «Хелпера» остаются.

Если на сервере роль «Хелпер» называется иначе или оформлена значками
(например, `⌊🔰⌉│Хелпер`), бот найдёт её по вхождению названия. Если роли нет совсем,
снимаются только роли, выданные ботом, и сохранённая в карточке должность.

Имена можно переопределить в `.env`:

```env
HELPER_ROLE_NAME=Хелпер
PLAYER_ROLE_NAME=Игрок
```

Снятие — это **не** кик и **не** бан: участник остаётся на сервере, история и SteamID
сохраняются.

## Установка

1. Создайте бота: <https://discord.com/developers/applications> → **New Application** → **Bot**.
2. На вкладке **Bot** включите `SERVER MEMBERS INTENT` (нужен для работы с ролями).
3. Скопируйте токен (**Reset Token**).
4. Пригласите бота с правами `Manage Roles`, `Send Messages`, `Embed Links`,
   `Read Message History`.

   ```
   https://discord.com/oauth2/authorize?client_id=CLIENT_ID&scope=bot%20applications.commands&permissions=309506165762
   ```

   > **Важно:** в ссылке обязательно должен быть `scope=bot`. Если пригласить приложение
   > только с `applications.commands`, команды в списке появятся, но бот не зайдёт на сервер,
   > и Discord будет писать «Приложение не отвечает».
5. Установите зависимости:

```bat
python -m pip install -r requirements.txt
```

6. Скопируйте `.env.example` в `.env` и заполните:

```env
DISCORD_TOKEN=ваш_токен
GUILD_ID=123456789012345678
```

`GUILD_ID` — ID сервера (режим разработчика → правый клик по серверу → «Копировать ID»).
С ним команды появляются сразу; без него — глобально, до часа.

7. Запуск:

```bat
run.bat
```

или

```bat
python bot.py
```

Проверка без Discord:

```bat
python bot.py --selftest
```

## Первичная настройка

1. **Поднимите роль бота** выше всех ролей администрации.
2. Привяжите каналы:

```
/канал тип: Кадровый аудит          канал: #кадровый-аудит
/канал тип: Варны и предупреждения  канал: #варны
/канал тип: Чёрный список           канал: #чёрный-список
/канал тип: Общие логи              канал: #общие-логи
/канал тип: Новости и обновления    канал: #новости
```

Каналы могут быть текстовыми или форумом (тогда каждое событие — отдельный пост).

3. Проверьте `/статус`: бот на связи, каналы ✅, роли «Хелпер» и «Игрок» найдены,
   роль бота выше нужных.

## Новости и обновления

`/новость` собирает красивое сообщение по шаблону: версия, номер билда и разделы изменений.

- `/новость добавили: новая команда исправили: баг с ролями` — первый выпуск получает
  версию **1.0** и **build #1**, дальше патчи считаются сами: 1.1, 1.2, ...
- `/новость версия: 2.0 добавили: крупное обновление` — крупная версия вручную.
  Формат `2.6` = крупная версия **2** и **6** патчей.
- Разделы: `добавили`, `изменили`, `исправили`, `убрали`. Каждый пункт — с новой строки.
  `текст` — обычное описание, `заголовок` — свой заголовок.
- `/новость заголовок: Технические работы текст: ...` — обычная новость без версии
  и без увеличения билда.
- Билд увеличивается на каждом обновлении; текущая версия и билд видны в `/статус`.
- Версия и билд хранятся отдельно для каждого сервера, поэтому на основном сервере
  отсчёт начнётся с **1.0 / build #0**.
- Когда выходит новая версия самого бота, он один раз публикует запись об этом
  в канале новостей (независимо от версии сервера).

## Если Discord пишет «Приложение не отвечает»

Это значит, что до бота не дошёл запрос. По порядку:

1. **Процесс бота не запущен.** Команды в Discord остаются в списке даже когда бот офлайн.
   Запустите `run.bat` и не закрывайте окно — он сам перезапускает бота при падении.
2. **Бот установлен без `scope=bot`.** Самая частая причина: команды видны, а бота нет на сервере.
   Проверка — `/статус`, поле «Серверов у бота»: если `0`, перепригласите по ссылке из шага 4.
   В `bot.log` при старте будет строка `БОТ НЕ ДОБАВЛЕН НИ НА ОДИН СЕРВЕР`.
3. **Кнопки на старом сообщении.** После перезапуска кнопки на старых панелях мертвы.
4. **Не тот сервер.** Бот отвечает только там, куда его пригласили и где совпадает `GUILD_ID`.
5. **Нет права «Использовать команды приложения»** в канале — проверьте права канала для бота.
6. **Форум/войс вместо текстового канала** — бот скажет об этом текстом, а не промолчит.

Что именно произошло, видно в файле `bot.log` рядом с ботом: он пишется всегда, даже если
окно консоли закрыто. Каждое нажатие команды пишется строкой `interaction ...`.

## Перенос с тестового сервера на основной

1. Пригласите бота на основной сервер по ссылке из шага 4 (с `scope=bot`).
2. Узнайте ID основного сервера (режим разработчика → правый клик → «Копировать ID»).
3. В `.env` укажите оба сервера — команды будут сразу на обоих:

```env
GUILD_IDS=1569743432887308442,123456789012345678
```

4. Перенесите данные:

```bat
python migrate.py --list
python migrate.py --from 1569743432887308442 --to 123456789012345678
```

Флаг `--overwrite` удаляет данные целевого сервера перед импортом (спросит подтверждение).

5. На основном сервере привяжите каналы (`/канал`) и проверьте `/статус`.
   Роли привязывать не нужно: бот берёт их с сервера в момент выдачи.
   Сохранённые названия должностей переносятся, ID ролей — нет, поэтому после переноса
   обновите должности командой `/повышение` или `/понижение` (уже с ролями основного сервера).
6. Когда всё работает, оставьте в `.env` только основной сервер:

```env
GUILD_ID=123456789012345678
```

## Хранение данных

SQLite-файл `data/audit.db` рядом с ботом: настройки, каналы, администраторы,
варны, предупреждения, история действий, чёрный список. Все данные привязаны к `guild_id`,
поэтому в одной базе спокойно живут несколько серверов. Удалите файл, чтобы сбросить всё.

Лог: `bot.log` в папке бота (кодировка UTF-8).

## Структура

| Файл | Что внутри |
|---|---|
| `bot.py` | команды, проверки прав, SteamID и иерархии ролей, отправка карточек и логов |
| `database.py` | SQLite: схема, запросы, миграция старой базы |
| `formatting.py` | тексты и embed-карточки в двух стилях |
| `views.py` | подтверждение снятия и листалка истории |
| `config.py` | чтение `.env` |
| `updates.py` | версия бота и текст обновления для автопоста |
| `migrate.py` | перенос данных между серверами |
| `list_commands.py` | вывод дерева команд без подключения |

## Замечания

- Предупреждения `PyNaCl is not installed` / `davey is not installed` — про голос, можно игнорировать.
- Если бот не может изменить роли: проверьте, что его роль выше и есть право `Manage Roles`.
- SteamID принимается в виде `STEAM_0:1:1234567` или `76561198000000000`.
- Варны и предупреждения — разные вещи: лимит (`/лимит`) считается по варнам,
  предупреждения показываются количеством.
